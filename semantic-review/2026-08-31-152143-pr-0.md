# Semantic cassette record/replay for LLM agent tests

The implementation adds semantic JSON cassettes, provider adapters, serialized record/replay clients, Vitest/Jest wrappers, and a management CLI. Strict TypeScript, zero declared runtime dependencies, and ESM/CommonJS outputs are present and load successfully; all 12 tests pass. **Confirmed:** blocking gaps remain where matching and provider normalization collapse behaviorally different agent turns, while CI configuration and cassette naming can select live or unrelated data.

**Watch for:** **confirmed** stale replay when tool results or prior decisions change; **confirmed** OpenAI and Google request semantics dropped during normalization; **confirmed** invalid `AGENTCASSETTE_MODE` values falling back to live-capable `auto`; **confirmed** distinct cassette names mapping to the same JSON file.

**Verdict**: NEEDS_CHANGES

## High-level view

Replay is gated solely by the configured fingerprint. **Confirmed:** the default omits all prior message values except the final user turn, so changed tool outputs or assistant decisions can receive a stale response even though the stored request differs.

Provider normalization drops important request semantics. **Confirmed:** OpenAI assistant `tool_calls` disappear, Google tools/system instructions under `config` are ignored, and Anthropic mixed text/tool-result blocks are reordered. **Confirmed:** replay objects are cast to the caller's generic response type despite omitting standard provider fields.

**Confirmed:** cassette path sanitization aliases distinct names and reads do not verify the embedded name. **Confirmed:** invalid test-runner mode overrides silently fall back to `auto`, which can call a live provider when no cassette exists.

**Confirmed:** `includeDefaults: false` leaves built-in string redaction active, while custom cassette directories make adapters and `stats` use different default usage files.

**Confirmed:** CLI pruning relies on literal source substrings, cassette parsing does not validate turns, and no CLI command has automated coverage.

<details><summary>Details</summary>

## Tool-result changes can reuse an unrelated recorded turn

`defaultFingerprint` includes tool names/schemas, message roles/content-part types, and normalized text from the last user message (`src/core/fingerprint.ts:6-21`). **Confirmed:** it excludes tool-message values, prior assistant/user content, and historical tool-call arguments; requests with tool results of 10 and 40 therefore hash identically, and `createCassetteClient` checks only that digest before replay (`src/core/client.ts:80-93`). A changed live tool result can silently return the old next decision instead of `CassetteDivergenceError`. Include normalized tool results and historical decisions by default, with explicit exclusions for volatile fields, and add a multi-turn regression test.

## OpenAI request history loses assistant tool calls

OpenAI historical messages pass through `messageFromUnknown` (`src/providers/openai.ts:17-24`), which keeps only role, content, name, and tool-call ID (`src/core/canonical.ts:89-100`). **Confirmed:** an assistant message containing only `tool_calls` becomes `{ role: "assistant", content: [] }`; function name, arguments, and ID disappear. Preserve historical calls in the semantic request and test a complete user → assistant tool call → tool result sequence.

## Google adapter ignores SDK `config` semantics

The Google normalizer reads `systemInstruction` and `tools` only from the request root (`src/providers/google.ts:15-38`), and shared tool normalization handles `functionDeclarations` with `parameters` (`src/providers/common.ts:26-39`). **Confirmed:** `config.systemInstruction`, `config.tools`, and `parametersJsonSchema` produce no system message or tools. Support and document concrete Google SDK request layouts, with fixtures built from those contracts.

## Anthropic mixed blocks are reordered

Anthropic normalization collects non-`tool_result` blocks before appending all tool results (`src/providers/anthropic.ts:19-30`). **Confirmed:** tool result, text, tool result becomes text, first result, second result. Preserve block order when splitting messages or reject unsupported mixed ordering.

## Synthesized responses do not satisfy the promised response type

Each adapter casts a hand-built object to the caller-selected `Response` (`src/providers/openai.ts:5-11`, `src/providers/anthropic.ts:5-11`, `src/providers/google.ts:5-11`). **Confirmed:** OpenAI replay omits `model` (`src/providers/openai.ts:51-77`), Anthropic omits `model` and `stop_sequence` (`src/providers/anthropic.ts:58-82`), and Google cannot recreate SDK class helpers (`src/providers/google.ts:71-89`). Code reading these fields differs between record and replay despite compiling against the asserted type. Preserve supported fields, narrow the public replay types, or require adapter-specific reconstruction callbacks; contract-test the same consumer against live-shaped and replayed values.

## Invalid CI mode overrides fail open

`environmentMode` returns `undefined` for every value outside the three accepted strings (`src/adapters/testing.ts:50-53`), after which the wrapper falls back to the option or `auto` (`src/adapters/testing.ts:16-20`). **Confirmed:** `AGENTCASSETTE_MODE=repaly` with no cassette can record through the real client. Reject present-but-invalid values with an error listing accepted modes.

## Cassette name sanitization aliases distinct clients

`pathFor` replaces unsupported runs with `-` (`src/core/storage.ts:61-64`). **Confirmed:** `tenant/a` and `tenant-a` both map to `tenant-a.json`; `parseCassette` receives the expected name but never compares it with the stored name (`src/core/storage.ts:31-33`, `src/core/storage.ts:93-97`). `auto` can replay the first logical cassette for the second, and record mode can overwrite it. Reject unsafe names, encode them reversibly, or add a digest, then validate the embedded name on read.

## `includeDefaults` leaves default PII redaction active

`includeDefaults: false` removes only `defaultRedactionRules` (`src/core/redaction.ts:34-39`). **Confirmed:** bearer, email, and phone replacements remain unconditional (`src/core/redaction.ts:53-58`). Gate all built-ins on the option or expose separate key/PII controls.

## Custom directories split usage writes from `stats` reads

The test wrappers default to `.agentcassette/usage.ndjson` regardless of cassette directory (`src/adapters/testing.ts:16-29`), while the CLI derives usage from the directory's parent (`src/cli/index.ts:20-24`). **Confirmed:** `/tmp/run/cassettes` writes and reads different default usage files, so `stats` reports no tracked savings. Derive one shared default from the effective cassette directory.

## `prune` can delete dynamically referenced cassettes

Prune/verify recognize a reference only when the complete name appears as a source substring (`src/cli/index.ts:179-188`). **Confirmed:** names built from parameters or concatenation are classified unused and `prune --yes` deletes them; unrelated substrings can also create false references. Use runtime metadata or a manifest as deletion authority and keep source scanning advisory.

## `verify` accepts malformed turn structures before crashing

`parseCassette` checks only top-level fields and that `turns` is an array (`src/core/storage.ts:99-107`). **Confirmed:** `turns: [null]` passes, then verify dereferences `turn.index` (`src/cli/index.ts:121-128`) instead of reporting a format error. Validate each turn and semantic request/response at the storage boundary.

## CLI and multi-turn provider gaps are outside the test suite

**Confirmed:** no tests invoke list, prune, verify, or stats, and fixtures omit OpenAI historical `tool_calls`, Google `config`, Anthropic mixed blocks, provider response consumers, invalid modes, name collisions, and malformed cassettes (`test/client.test.ts`, `test/providers.test.ts`, `test/adapters.test.ts`, `test/redaction-storage.test.ts`). Add end-to-end CLI tests and provider contract fixtures for these paths.
