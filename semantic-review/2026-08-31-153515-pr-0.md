# Follow-up hardening of semantic cassette replay

The fixes close most prior blockers: changed tool results and assistant tool decisions now diverge; OpenAI history and Google `config` schemas normalize correctly; invalid modes fail closed; cassette identity, redaction defaults, usage paths, and baseline CLI coverage are repaired. Four behavioral gaps remain in history matching, Anthropic response ordering, prune authority, and structural validation. No newly introduced high-severity correctness issue was found beyond the still-incomplete history fingerprint.

**Watch for:** **confirmed [High]** stale replay when an earlier user turn changes but the final user turn and assistant/tool history remain the same; **confirmed [Medium]** `prune --yes` still trusts machine-local usage as deletion authority; **confirmed [Medium]** Anthropic mixed response blocks reorder during replay; **confirmed [Low]** malformed events and metadata still pass cassette parsing.

**Verdict**: NEEDS_CHANGES

## High-level view

The fingerprint repair covers changed tool results and historical assistant calls. **Confirmed:** it still omits every user message except the final one, so a materially changed earlier instruction can select the old response.

OpenAI history and Google SDK-shaped `config`, `systemInstruction`, `tools`, and `parametersJsonSchema` now survive normalization. The documented provider replay contract is explicitly plain data rather than a complete SDK object, but **confirmed:** Anthropic response normalization still cannot retain text/tool block interleaving.

Cassette file names now use a collision-free alphabet and reads verify embedded identity. Parsing checks turns, requests, responses, and tool calls, but **confirmed:** event payloads and metadata retain little or no validation despite the parser returning a fully typed `Cassette`.

Invalid runner modes throw, `includeDefaults: false` disables all built-ins, and custom directories derive the same usage path as CLI stats. The CLI directly tests list, stats, verify, and prune, but **confirmed:** prune protection still depends on source literals or an ignored local usage log, neither authoritative on a clean checkout.

## Earlier user instructions remain outside replay identity

`defaultFingerprint` records role/content shape, final-user text, and assistant/tool history. **Confirmed [High]:** prior user content is absent, so conversations differing only in an earlier instruction produce the same digest. A runtime check produced identical fingerprints for `user("first") → assistant("ack") → user("same final")` and the same history with `user("changed")`. Include normalized prior user turns while retaining explicit exclusions for system boilerplate and volatile timestamps.

The tool-result regression and OpenAI historical-call fixture do not exercise changed earlier user content.

## Anthropic response blocks still lose interleaving

Request normalization now preserves source block order. **Confirmed [Medium]:** response normalization splits text into `content` and calls into `toolCalls`, then replay emits all text before all calls. `tool_use → text → tool_use` therefore becomes `text → tool_use → tool_use`, changing sequential consumers. Preserve ordered response blocks in the semantic model or explicitly reject this shape, and cover response round trips rather than only request ordering.

## Runtime usage is not safe prune authority

Prune protects names seen in `usage.ndjson`. **Confirmed [Medium]:** that file is ignored, core `createCassetteClient` usage does not write it, and a clean checkout has no observations, so a dynamically constructed live cassette can still be deleted by `prune --yes`. The CLI test demonstrates deletion of an unobserved runtime-generated name rather than protection of a dynamic live name. Require a committed manifest, explicit candidate list, or per-item confirmation for destructive deletion.

## Cassette validation remains partial below each turn

**Confirmed [Low]:** event entries require only a string `type`, and `metadata` is not validated; an `output.final` event without `content` and numeric provider metadata passes `parseCassette` as a typed `Cassette`. Validate every `SemanticEvent` variant and metadata field, or narrow the “complete cassette structure” documentation claim.
